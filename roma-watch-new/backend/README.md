# روما واچ - بک‌اند (Node.js / Express)

## اجرا

```bash
cd backend
npm install
cp .env.example .env
npm start
```

سرور روی `http://localhost:4000` بالا میاد.
برای توسعه با ری‌استارت خودکار: `npm run dev`

## ساختار

```
backend/
  server.js              نقطه ورود
  src/
    app.js                تعریف اپ اکسپرس و اتصال روت‌ها
    config.js              تنظیمات (پورت، JWT و ...)
    db/store.js             خواندن/نوشتن فایل‌های JSON (دیتابیس ساده)
    middleware/auth.js       بررسی توکن JWT
    services/
      token.service.js       ساخت/بررسی JWT
      sms.service.js          ارسال OTP (فعلاً شبیه‌سازی‌شده)
    controllers/              منطق هر بخش
    routes/                    مسیرهای API
  data/                       فایل‌های JSON (دیتابیس) - خودکار ساخته میشن
```

دیتای محصولات مستقیم از `../data/products.json` (همون فایلی که فرانت‌اند
استفاده می‌کنه) خونده میشه، پس یه منبع دیتای واحد وجود داره.

## اتصال پنل پیامکی واقعی

الان فقط `backend/src/services/sms.service.js` کد OTP رو توی کنسول سرور
لاگ می‌کنه (پیامک واقعی ارسال نمیشه). وقتی API پنل پیامکیت (کاوه‌نگار،
ملی‌پیامک و ...) رو داشتی، فقط کافیه تابع `sendOtpSms` توی همون فایل رو
با یه `fetch` به سرویس موردنظر جایگزین کنی؛ بقیه پروژه به همون امضای
تابع وابسته‌ست و چیز دیگه‌ای نیاز به تغییر نداره. یه نمونه کد آماده هم
بالای همون فایل به عنوان کامنت گذاشته شده.

## API ها

| متد | مسیر | نیاز به لاگین | توضیح |
|---|---|---|---|
| GET | /api/products | - | لیست محصولات (فیلتر با query params: brand, gender, country, minPrice, maxPrice, discount=true, options, sort) |
| GET | /api/products/:id | - | جزئیات یک محصول |
| POST | /api/auth/send-otp | - | ارسال کد به شماره تلفن `{ phone }` |
| POST | /api/auth/verify-otp | - | تایید کد و گرفتن توکن `{ phone, code }` |
| GET | /api/auth/me | ✓ | اطلاعات کاربر لاگین‌شده |
| GET | /api/cart | ✓ | سبد خرید کاربر |
| POST | /api/cart | ✓ | افزودن `{ productId, qty }` |
| PATCH | /api/cart/:productId | ✓ | تغییر تعداد `{ qty }` |
| DELETE | /api/cart/:productId | ✓ | حذف از سبد |
| DELETE | /api/cart | ✓ | خالی کردن سبد |
| GET | /api/favorites | ✓ | لیست علاقه‌مندی‌ها |
| POST | /api/favorites/:productId | ✓ | افزودن/حذف (toggle) |
| POST | /api/orders | ✓ | ثبت سفارش از روی سبد خرید فعلی |
| GET | /api/orders | ✓ | لیست سفارش‌های کاربر |
| GET | /api/orders/track/:code | - | رهگیری عمومی سفارش با کد |

برای روت‌های نیازمند لاگین، هدر زیر لازمه:
```
Authorization: Bearer <token>
```

## نکته مهم درباره تست

من (کلود) توی محیطی که این پروژه رو ساختم دسترسی به اینترنت نداشتم،
پس نتونستم خودم `npm install` واقعی رو اجرا کنم و سرور رو با درخواست
HTTP واقعی تست کنم. به‌جاش:
- سینتکس همه فایل‌ها رو با `node --check` بررسی کردم (بدون خطا)
- منطق همه‌ی کنترلرها (فیلتر محصولات، OTP، سبد خرید، علاقه‌مندی‌ها،
  سفارش و رهگیری) رو با صدا زدن مستقیم توابع (بدون نیاز به اکسپرس)
  تست کردم و همه سناریوها (موفق و خطا) درست جواب دادن.

پس منطق کد قابل اطمینانه، ولی حتماً بعد از `npm install` یه تست سریع
با curl یا Postman هم خودت بزن که همه‌چی رو با چشم خودت ببینی. اگه به
مشکلی خوردی بگو تا سریع رفعش کنم.

## اتصال فرانت‌اند

فایل `api.js` (کنار فایل‌های فرانت‌اند) آدرس بک‌اند رو به این شکل صدا
می‌زنه:
```js
const BASE_URL = "http://localhost:4000/api";
```
اگه بک‌اند رو جای دیگه (دامنه/پورت متفاوت) دیپلوی کردی، فقط همین یه
خط رو توی `api.js` عوض کن.

برای کاربر مهمان (لاگین‌نکرده)، سبد خرید و علاقه‌مندی‌ها دقیقاً مثل
قبل با `localStorage` کار می‌کنن. وقتی کاربر لاگین کنه، این دیتا با
سرور سینک میشه.
